# report_039

本レポートは，`.orders/order_039.md` の指示に基づき実施した，実験ex0051（条件B：バッチサイズ
512・学習率0.001）における「SGDのみエポック数を倍にした追加学習」の実装内容と結果をまとめた
ものである。条件Bの基本条件・他手法との比較等は`.reports/report_036.md`を参照。

## 1. 目的

ex0024（`report_038.md`）において，SGDのみエポック数を倍にした追加学習を行った結果，全
バッチサイズで精度が向上することが確認された。本実験は，この知見がCIFAR-10・AlexNetとは
異なるデータセット・アーキテクチャ（Imagewoof・ResNet18）でも成立するかを確認するため，
ex0051の条件B（バッチサイズ512・学習率0.001・$\lambda=5\times10^{-4}$，`.orders/order_036.md`）
と同一の条件のまま，SGDのみエポック数を2倍（505→1010）に延長した追加学習を実施した。

## 2. 実装

`programs/ex0051_imagewoof_resnet18_bs128_longrun/train.py`に，`SGD_DOUBLE_EPOCH_CONDITION`
（条件Bの`batch_size`・`learning_rate`はそのまま，`epochs`のみ$505\times2=1010$）を追加し，
`_build_sgd_double_epoch_tasks`関数でSGD×5Seed＝5条件のタスクを生成する
`run_sgd_double_epoch_phase`関数を実装した。`run_single_experiment`は既にタプル引数
`(method, batch_size, eta, epochs, seed)`でエポック数を明示的に受け取る設計（`.orders/
order_036.md`拡張時に実装済み）であったため，変更は不要であった。`main`関数に
`run_sgd_double`引数を追加し，`run_bs128_phase`・`run_bs512_phase`と独立に実行できるように
した（ex0024・`.orders/order_038.md`と同種の2フェーズ実行パターン）。

## 3. 実行前の計算コスト見積もりと実測との比較

条件Bの実測`elapsed_time`（4プロセス並列実行下，資源競合を含む実測値）から，1エポックあたり
所要時間（約83.4秒）を算出し，2倍のエポック数（1010）に適用したところ，単一タスクあたり
約23.4時間と見積もられた。VRAM使用量はバッチサイズ512では手法によらず約22.5GB（reserved
ベース，`report_036.md`のパイロット計測でSGD単独でも22.52GB）であるため，条件Bと同様に4
プロセス並列とした。**5Seedに対し4プロセス並列であるため2ラウンドとなり（1ラウンド目4Seed，
2ラウンド目1Seed），見積もり総所要時間は単一タスクの所要時間の約2倍の約46.8時間（約1.95日）**
と算出し，学習開始前にユーザーへ報告した。

**実測との比較**：実際の総所要時間は，1ラウンド目が約22.9時間，2ラウンド目（5番目のSeed）も
約22.9時間であり，合計約45.8時間であった。見積もり（約46.8時間）とほぼ一致した。

## 4. 結果

### 4.1 エポック数延長によるSGDの精度向上

| 条件 | 最終精度（平均±標準偏差） | 最高精度（平均） |
|---|---|---|
| 元のエポック数（505エポック） | 0.4472±0.0090 | 0.4753 |
| 倍エポック数（1010エポック） | **0.4802±0.0235** | **0.5246** |

**エポック数の倍増により最終精度が3.30ポイント向上した**（0.4472→0.4802）。これはex0024
（`report_038.md`）で確認された「SGDはエポック数の延長により精度が向上する」という傾向を，
Imagewoof・ResNet18という異なるデータセット・アーキテクチャでも再現する結果である。

ただし，ex0024の結果（標準偏差が減少しながら精度が向上し，バッチサイズ512・128では明確に
プラトーに達した）とは異なり，**本実験では標準偏差がむしろ増大した**（0.0090→0.0235）。
これは4.2節で述べる通り，1010エポック時点でも学習曲線が大きく振動しており，Seedによって
到達する精度にばらつきが生じているためである。

### 4.2 プラトー判定（3指標，窓幅$W=10$，Seed平均軌跡，`report_035.md` 2.3節と同一の閾値）

| 指標 | 値 |
|---|---:|
| 隣接相対変化 | 0.0843 |
| 正味変化量 | 0.0577 |
| 回帰の相対傾き | 0.00185 |
| **判定** | **未プラトー（3指標全て閾値超過）** |

**1010エポック時点でもSGDは未プラトーであった**。末尾15エポックのSeed平均精度軌跡（0.486→
0.485→0.467→0.492→0.454→0.451→0.490→0.462→0.496→0.488→0.468→0.455→0.470→0.468→0.480）を
目視で確認すると，明確な上昇トレンドではなく，0.45〜0.50の範囲で大きく振動していることが
分かる。ex0024（バッチサイズ32のSGD）で見られた「緩やかだが単調に近い上昇」とは異なり，
**本実験では振動そのものが収まっていない状態**であり，機械的判定（未プラトー）は目視確認と
一致する。

### 4.3 他手法との比較（条件B，元のエポック数）

| 手法 | 最終精度 |
|---|---|
| SGD（1010エポック，本実験） | 0.4802±0.0235 |
| SGD（505エポック，report_036.md） | 0.4472±0.0090 |
| SVRG（505エポック） | 0.4414±0.0214 |
| NFG SVRG（505エポック） | 0.2846±0.0645 |
| ASAI SVRG（505エポック，プラトー到達済み） | 0.4886±0.0035 |

倍エポックのSGD（0.4802）は，元のエポック数のSVRG（0.4414）を上回り，プラトーに達している
ASAI SVRG（0.4886）にほぼ匹敵する水準まで到達した。ただし，SGDは4.2節で述べた通り未プラトー
かつ標準偏差が大きく，ASAI SVRGのように安定してこの精度に収束しているわけではない点に注意
を要する。SVRG側はエポック数を延長した結果ではないため，これは対等な比較ではなく，「SGDが
元のエポック数では過小評価されていた」ことを示す結果と解釈すべきである（`report_038.md` 5.1節
と同様の注意点）。

## 5. 考察

### 5.1 ex0024との比較：データセット・アーキテクチャ間での一般性

ex0024（CIFAR-10・AlexNet）・本実験（Imagewoof・ResNet18）のいずれにおいても，SGDはエポック
数の延長により精度が向上した。この点で「SGDが相対的に収束が遅い」という傾向は，データ
セット・アーキテクチャによらず一般的に成立する可能性がある。一方，**ex0024ではバッチサイズ
512・128で倍エポックにより明確にプラトーへ到達したのに対し，本実験（Imagewoof・ResNet18・
バッチサイズ512）では1010エポック時点でも未プラトーであり，標準偏差もむしろ増大した**。
この違いは，モデル・データセットの複雑さ（ResNet18・Imagewoofの方がAlexNet・CIFAR-10より
表現力・タスクの難度が高い）や，バッチサイズあたりの総イテレーション数（条件Bは$K=18$と
1エポックあたりの反復回数が少ない）に起因する可能性があるが，本実験の結果のみからは要因を
特定できない。

### 5.2 report_036.mdの結論への影響

report_036.mdでは，条件B（バッチサイズ512）がASAI SVRGの終盤崩壊への有効な対策であると
結論づけたが，この結論はASAI SVRGの崩壊回避・プラトー到達・オラクル呼び出し効率の回復という
複数の独立した証拠に基づいており，SGDの学習進捗とは無関係である。したがって，**本実験の
結果（SGDが元のエポック数では未収束であった）は，report_036.mdの主要な結論には影響しない**。
ただし，report_036.md 5.4節の「SGD最終精度0.4472±0.0090」という数値が，SGDにとって完全に
収束した状態での値ではなかったことは，本実験により新たに判明した事実である。

## 6. 未解決の論点・今後の検討候補

1. **SGDのさらなる延長の要否**：1010エポック時点でも未プラトーであり，さらなる延長でどこ
   まで精度が伸びるか，あるいはASAI SVRGの水準（0.4886）を上回るのかは未検証である。
2. **標準偏差が増大した原因**：エポック数の延長にもかかわらず標準偏差が減少せず増大した
   原因（学習率0.001が長期学習に対して大きすぎる可能性，データ順序の違いによるSeed間の
   感度の違い等）は本実験からは特定できない。
3. **ex0024とex0051で収束性の傾向が異なる原因**：5.1節で述べた通り，バッチサイズ・エポック
   数の倍増に対する応答がデータセット・アーキテクチャにより異なることの要因（モデルの
   表現力，1エポックあたりの反復回数$K$の違い等）の特定には，追加の実験が必要である。
