# `.orders/order_040.md`

## 1. ユーザーからの指示（原文）

同様の実験を条件を維持したままバッチサイズを32にして実施して。この際，エポック数は全部の
手法で統一してください。ただし，終了時点のモデルの重みと手法の内部状態やデータのシャッフルの
順番などを保存して，のちにエポック数を増やす実験を実施する前提にしてください。

## 2. 指示の解釈

`programs/ex0051_imagewoof_resnet18_bs128_longrun/`の条件B（バッチサイズ512・学習率0.001・
$\lambda=5\times10^{-4}$，`.orders/order_036.md`）と同様の実験を，バッチサイズのみ32に
変更して実施する（新条件「条件C」）。学習率（0.001）・正則化係数（$\lambda=5\times10^{-4}$）・
比較手法（SGD, SVRG, NFG SVRG, ASAI SVRG）・Seed数（5）はそのまま維持する。

「エポック数は全部の手法で統一」とは，既存の`CONDITIONS`構造（`{"batch_size", "learning_
rate", "epochs"}`の辞書を`itertools.product(METHODS, CONDITIONS, SEEDS)`で展開する設計）が
既に満たしている性質（1つの条件につき単一のエポック数を全手法に適用する）を条件Cでも維持する
ことを意味する。手法ごとにオラクル呼び出し回数を揃えるために手法別にエポック数を変える，
といった変更は行わない。

エポック数は，条件B・条件Aと同様に，基準条件（バッチサイズ128・128エポック・$K=71$，総
イテレーション数$128\times71=9088$）に総イテレーション数を揃える方針
（`.orders/order_036.md` 3節）を踏襲し，$K=\lceil9025/32\rceil=283$より
$\lceil9088/283\rceil=33$エポックとする（総イテレーション数$33\times283=9339$，基準条件から
+251，+2.8%の端数。条件Bの端数（+0.022%）より大きいことをレポートに明記する）。

### 2.1 チェックポイント保存（今回の実装の中心的要求）

「終了時点のモデルの重みと手法の内部状態やデータのシャッフルの順番などを保存」とは，将来
エポック数を増やして学習を継続する追試験を可能にするため，各条件の学習終了時点で以下を
`checkpoint.pth`として保存することを指す。

- モデルの重み（`model.state_dict()`．SVRG系手法は現在のパラメータ$w_S^K$）
- スナップショットモデルの重み（`snapshot_model.state_dict()`．SVRG系手法のみ，$z_S$）
- Optimizerの内部状態（`optimizer.state_dict()`：スナップショット勾配，スナップショット
  パラメータ候補，ASAI SVRGの平均勾配・平均パラメータの累積等，`self.state`に保持される
  全ての値）
- Optimizer固有の非`state_dict`属性（`K`，`_step_count`，`_target_k`）
- データのシャッフル順序を決定する`torch.Generator`の状態（`train_dataloader.generator.
  get_state()`）
- SVRG・NFG SVRGのスナップショット点選択に用いる`numpy.random.Generator`の状態
  （`rng.bit_generator.state`）
- 現在のエポック数，累積オラクル呼び出し回数，累積`elapsed_time`，最高精度

本オーダーでは，チェックポイントの保存機構の実装・検証（保存した状態から同一のOptimizer
内部状態・シャッフル順序を再構築できることの単体テストによる確認）までを対象とし，実際に
チェックポイントから学習を再開してエポック数を延長する実験自体は，本オーダーの対象外とし
別オーダーで実施する（ユーザー指示の「前提にしてください」に対応）。
