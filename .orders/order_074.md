## 2. 指示の解釈

- `実験指示E6.md`（ユーザーが作成した E6 の指示書）は，別のPCでリポジトリをクローンした後に Claude Code へ与える指示書である．
- 本PCでは，クローン先で指示書どおりに実行できる状態にする．具体的には次を行う．
  1. 指示書の記述（参照するファイル，関数，引数，パス，既存の結果の有無，番号）をリポジトリの実物と照合する．
  2. 指示書2節の実装（`ex011_e6_cifar10_final_bs32_512/`，`analysis_e6.py`，`tests/test_e6_programs.py`）を本PCで先に作成する．
     - クローン先の作業を，一致の確認・本実行・集計・レポートに絞る．これにより，クローン先での実装の誤りの余地を減らす．
     - 実装は指示書2節のとおりとする．ex007 の4ファイルを変更せずにコピーし，`e2_runner.py` を2点だけ変え，`train.py` の `SPEC` を変える．
  3. 本PCで短い一致の確認を行う．
     - 付録B（`ex004`）と同じ GPU であるため，指示書3.2節の確認はビット単位で一致するはずである．
     - 指示書3.1節の E2（`ex007`）は RTX 3090 で実行されたため，本PCでは `oracle_calls` と0エポック目の一致のみを期待する．
  4. 実装済みであることと本PCでの確認の結果に合わせて，`実験指示E6.md` を改める．
- 番号の割り当てを次のとおり改める．
  - 本PCの次の番号は `order_074` である．そのため本指示を `order_074` とし，E6（クローン先）の指示とレポートは `order_080`／`report_080` とする．
  - 実験のディレクトリ `ex011` は E6 に割り当てたまま，本PCは今後 `ex012` 以降と `order_075`〜`order_079` を使う．
- 本PCでは E6 の本実行（20試行）は行わない．
- `programs_review/document.md` の E6 の追記は，結果の統合時に行う（指示書の方針どおり）．
- Git の commit・push は行わない．クローン先で使うには，ユーザーが本PCの変更を commit・push する必要がある．
